<objective>
Fix container runtime bug where is_connected is called incorrectly during shutdown.

Root Cause: Line 113 in container.py calls `adapter.is_connected` which is a property
that returns a bool synchronously. However, the verification flagged this because
the adapters have both a property and potentially async behavior.

Upon inspection, the adapters define `is_connected` as a property (not async method):
```python
@property
def is_connected(self) -> bool:
    return self._executor is not None and self._executor.is_connected
```

So the actual bug is that `is_connected` checks `self._executor.is_connected` which
may be an async property on the executor, not the adapter.

Solution: Ensure shutdown handles any potential async behavior gracefully.

Output: Container shutdown works correctly without runtime errors.
</objective>

    ```python
    async def shutdown(self) -> None:
        """Cleanup all connections."""
        if self._event_publisher:
            try:
                await self._event_publisher.disconnect()
            except Exception:
                pass  # Ignore errors during shutdown

        for broker_type, adapter in self._broker_adapters.items():
            try:
                # is_connected is a property, not async
                if adapter.is_connected:
                    await adapter.disconnect()
            except Exception:
                # Log but don't fail shutdown
                pass

        self._initialized = False
    ```

    The key changes:
    1. Wrap each disconnect in try/except to prevent one failure from blocking others

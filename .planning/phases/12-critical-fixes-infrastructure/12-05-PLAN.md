<task type="auto">
  <name>Task 1: Create production environment files</name>
  <files>ui-next/.env.production, ui-next/.env.example</files>
  <action>
    Create production environment file for Next.js frontend.

    Create ui-next/.env.production:
    ```
    # Production Backend URLs
    BACKEND_URL=http://localhost:8765
    NEXT_PUBLIC_BACKEND_URL=https://api.tradeflow.fluxeo.net
    NEXT_PUBLIC_WEBHOOK_BASE_URL=https://api.tradeflow.fluxeo.net

    # WebSocket URL (derived from NEXT_PUBLIC_BACKEND_URL by websocket-provider.tsx)
    # Uses wss:// protocol automatically
    ```

    Note: BACKEND_URL stays localhost because Next.js API routes run server-side
    and connect to backend on same machine. NEXT_PUBLIC_* vars are for client-side.

    Update ui-next/.env.example to document production values:
    ```
    # Backend URL (server-side API calls - internal)
    BACKEND_URL=http://localhost:8765

    # Backend URL (client-side, for WebSocket connection)
    # Development: http://localhost:8765
    # Production: https://api.tradeflow.fluxeo.net
    NEXT_PUBLIC_BACKEND_URL=http://localhost:8765

    # Public webhook URL (displayed to users for webhook configuration)
    # Development: http://localhost:8765
    # Production: https://api.tradeflow.fluxeo.net
    NEXT_PUBLIC_WEBHOOK_BASE_URL=http://localhost:8765
    ```
  </action>
  <verify>cat ui-next/.env.production shows correct production URLs</verify>
  <done>Production environment file created with public URLs</done>
</task>

<task type="auto">
  <name>Task 2: Configure backend to bind to LAN IP</name>
  <files>app/core/config.py</files>
  <action>
    Update backend configuration to allow binding to LAN IP instead of just localhost.

    In app/core/config.py, add HOST configuration:

    ```python
    # Server binding configuration
    HOST: str = "0.0.0.0"  # Bind to all interfaces (allows LAN access)
    PORT: int = 8765
    ```

    If HOST is already defined, ensure default is "0.0.0.0" not "127.0.0.1".

    This allows:
    - Caddy to proxy to localhost:8765
    - Direct LAN access if needed
    - Docker networking to work

    The run_backend.py or main.py should use these settings:
    ```python
    uvicorn.run(app, host=settings.HOST, port=settings.PORT)
    ```

    Check if this is already implemented. If not, update the relevant startup script.
  </action>
  <verify>grep -i "host" app/core/config.py shows HOST configuration</verify>
  <done>Backend configured to bind to accessible address</done>
</task>

<task type="auto">
  <name>Task 3: Update Docker configuration for production</name>
  <files>ui-next/Dockerfile</files>
  <action>
    Verify the Next.js Dockerfile is ready for production:

    1. Check it uses standalone output mode (already configured in next.config.mjs)
    2. Ensure environment variables are passed at runtime, not build time
    3. Verify port 3456 is exposed

    Update Dockerfile if needed:
    ```dockerfile
    # Build stage
    FROM node:20-alpine AS builder
    WORKDIR /app
    COPY package*.json ./
    RUN npm ci
    COPY . .
    RUN npm run build

    # Production stage
    FROM node:20-alpine AS runner
    WORKDIR /app
    ENV NODE_ENV=production
    ENV PORT=3456

    # Copy standalone build
    COPY --from=builder /app/.next/standalone ./
    COPY --from=builder /app/.next/static ./.next/static
    COPY --from=builder /app/public ./public

    EXPOSE 3456

    CMD ["node", "server.js"]
    ```

    The key is that NEXT_PUBLIC_* variables are baked in at build time,
    so production builds must use .env.production or build args.
  </action>
  <verify>cat ui-next/Dockerfile shows production-ready configuration</verify>
  <done>Docker configuration verified for production deployment</done>

<task type="checkpoint:human-action" gate="blocking">
  <action>Configure Caddy reverse proxy for public URLs</action>
  <instructions>
    The application is ready for production deployment. Configure your Caddy server:

    **Caddyfile configuration:**
    ```
    tradeflow.fluxeo.net {
        reverse_proxy localhost:3456
    }

    api.tradeflow.fluxeo.net {
        reverse_proxy localhost:8765
    }
    ```

    **Steps:**
    1. Add the configuration to your Caddyfile
    2. Ensure DNS for tradeflow.fluxeo.net and api.tradeflow.fluxeo.net points to your server
    3. Restart Caddy: `sudo systemctl reload caddy`
    4. Caddy will automatically obtain SSL certificates via Let's Encrypt

    **Verification:**
    - https://tradeflow.fluxeo.net should show the Tradeflow login page
    - https://api.tradeflow.fluxeo.net/health should return {"status": "healthy"}

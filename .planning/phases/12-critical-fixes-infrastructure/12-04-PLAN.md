<task type="auto">
  <name>Task 1: Fix webhook configs API error handling</name>
  <files>ui-next/src/app/api/webhook-configs/route.ts</files>
  <action>
    The webhook configs API may fail for several reasons. Improve error handling:

    1. Check if backend endpoint exists at /api/v1/webhook-configs/
       - May return 404 if endpoint doesn't exist
       - May return 401 if auth required but token missing
       - May return 500 if backend error

    2. Return empty array instead of error when:
       - User is logged in but has no webhook configs (normal case)
       - Backend returns 404 (endpoint may not exist yet)

    3. Only return error for actual problems:
       - 401 Unauthorized (user not logged in)
       - 500+ server errors (backend down)

    Updated implementation:
    ```typescript
    export async function GET() {
      try {
        const token = await getTokenFromCookies();

        if (!token) {
          return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
        }

        const response = await fetch(`${BACKEND_URL}/api/v1/webhook-configs/`, {
          headers: { 'Authorization': `Bearer ${token}` },
        });

        // Handle 404 gracefully - user just has no configs yet
        if (response.status === 404) {
          return NextResponse.json([]);
        }

        if (!response.ok) {
          // Log error but return empty for better UX
          console.error(`Backend returned ${response.status} for webhook-configs`);
          if (response.status === 401) {
            return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
          }
          // For other errors, return empty array to prevent UI crash
          return NextResponse.json([]);
        }

        const configs = await response.json();
        return NextResponse.json(configs);
      } catch (error) {
        console.error('Error fetching webhook configs:', error);
        // Return empty array on network errors to prevent UI crash
        return NextResponse.json([]);
      }
    }
    ```

    This way the UI shows "no configs" instead of error on first use.
  </action>

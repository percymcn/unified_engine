# Plan 09-02: Signal Routing Configuration

## Context

Phase 9 success criterion: "Signal routing rules can be configured (which signals go to which accounts)".

The `WebhookConfig` model exists in `app/models/database_models.py` with:
- `routing_rules` (JSON) - Complex routing logic
- `symbol_filter` (JSON) - Which symbols to accept
- `action_filter` (JSON) - Which actions to accept
- `default_account_id` - Default account for routing

Backend API endpoints for webhook configuration don't exist yet - need to create them.

## Goal

Create backend API for signal routing rules and build UI for configuring which signals route to which accounts.

## Prerequisites

- Plan 09-01 complete (accounts exist to route to)
- `WebhookConfig` model in database

### Task 3: Create Routing Types (Frontend)
Define TypeScript interfaces for routing configuration.

**File**: `ui-next/src/types/routing.ts`
```typescript
export interface RoutingRule {
  id: string;
  condition: {
    field: 'symbol' | 'action' | 'source' | 'strategy';
    operator: 'equals' | 'contains' | 'startsWith' | 'endsWith';
    value: string;
  };
  target_account_id: number;
  priority: number;
}

export interface WebhookConfig {
  id: number;
  name: string;
  webhook_key: string;
  source: 'tradingview' | 'trailhacker' | 'custom';
  default_account_id?: number;
  routing_rules: RoutingRule[];
  symbol_filter?: string[];
  action_filter?: ('buy' | 'sell' | 'close')[];
  is_active: boolean;
  total_signals: number;
  successful_signals: number;
  failed_signals: number;
  last_signal_at?: string;
  created_at: string;
}
```

## Notes

- Routing rules are evaluated in priority order (lowest first)
- If no rules match, signal goes to default_account_id
- If no default account, signal is logged but not executed
- Webhook key should be 32+ character random string

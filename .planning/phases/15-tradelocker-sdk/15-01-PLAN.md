# Plan 15-01: TradeLocker SDK Migration

## Objective
Migrate TradeLocker integration from custom HTTP/WebSocket implementation to official `tradelocker` Python SDK.

## Context
- **Phase**: 15 - TradeLocker SDK
- **Requirement**: SDK-01 (TradeLocker - 100% SDK coverage)
- **Current State**: Custom implementation in `tradelocker_executor.py` using httpx + socketio
- **Target State**: Official `tradelocker` package (v0.56.2+) with TLAPI class

## Success Criteria
1. TradeLocker adapter uses official `tradelocker` package
2. All existing TradeLocker functionality preserved
3. JWT authentication via SDK (not custom implementation)
4. Orders, positions, account data work via official SDK

## Research Summary

### Official SDK Analysis
- **Package**: `tradelocker` on PyPI (v0.56.2, Dec 2024)
- **Requirement**: Python 3.11+
- **License**: MIT
- **Maintainer**: TradeLocker (official)

### SDK vs Current Implementation

| Feature | Current (`tradelocker_executor.py`) | Official SDK (`TLAPI`) |
|---------|-------------------------------------|------------------------|
| Auth | Brand API key + WebSocket | Username/password/server + JWT |
| HTTP Client | httpx AsyncClient | Requests (sync) |
| WebSocket | python-socketio | Not exposed (internal) |
| Instruments | GET /instruments | `get_all_instruments()` |
| Price History | Not implemented | `get_price_history()` |
| Current Price | Not implemented | `get_latest_asking_price()` |
| Place Order | POST /trades/market | `create_order()` |
| Close Position | DELETE /positions/{id} | `close_position()` |
| Get Positions | GET /positions | (via orders/account) |
| Get Accounts | GET /accounts | (via authentication) |

### Key Differences
1. **Authentication Model Change**: Current uses Brand API (broker-level), SDK uses user credentials
2. **Sync vs Async**: SDK is synchronous, executor is async (need async wrapper)
3. **WebSocket**: SDK doesn't expose WebSocket API - may need to keep custom WS for real-time updates
4. **Account Retrieval**: SDK retrieves accounts during auth via `/auth/jwt/all-accounts`

### Task 2: Create SDK Wrapper
**File**: `app/brokers/tradelocker_sdk_wrapper.py` (NEW)
**Purpose**: Async wrapper around synchronous TLAPI
**Implementation**:
```python
from tradelocker import TLAPI
import asyncio
from concurrent.futures import ThreadPoolExecutor

class TradeLockerSDKWrapper:
    """Async wrapper for synchronous TradeLocker SDK"""

    def __init__(self, environment: str, username: str, password: str, server: str):
        self._executor = ThreadPoolExecutor(max_workers=3)
        self._tl = TLAPI(
            environment=environment,
            username=username,
            password=password,
            server=server
        )

    async def get_all_instruments(self):
        loop = asyncio.get_event_loop()
        return await loop.run_in_executor(self._executor, self._tl.get_all_instruments)

    async def create_order(self, instrument_id, quantity, side, type_):
        loop = asyncio.get_event_loop()
        return await loop.run_in_executor(
            self._executor,
            lambda: self._tl.create_order(instrument_id, quantity, side, type_)
        )

    async def close_position(self, order_id):
        loop = asyncio.get_event_loop()
        return await loop.run_in_executor(self._executor, lambda: self._tl.close_position(order_id))

    # ... additional methods
```

| Risk | Impact | Mitigation |
|------|--------|------------|
| SDK sync calls block event loop | High | ThreadPoolExecutor wrapper |
| SDK doesn't expose WebSocket | Medium | Keep custom WS for real-time |
| SDK auth model differs from Brand API | Medium | Support both credential types |
| Python 3.11+ requirement | Low | Already using 3.11+ |

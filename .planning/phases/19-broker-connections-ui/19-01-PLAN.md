# Plan 19-01: Backend Connection Test Endpoint

## Objective

Create a backend endpoint to test broker connections with provided credentials before saving, returning detailed status and error information.

## Context

**Phase Requirements:**
- CONN-02: Connection test button to validate credentials before save
- CONN-06: Clear error messages on connection failure

**Discovery Findings:**
- `/credentials/validate/{credential_id}` exists but has `# TODO: Implement service-specific validation`
- Need new endpoint to test credentials BEFORE account creation (credentials not yet saved)
- Each broker has different auth patterns (OAuth, API keys, login/password)
- Existing executors have connection methods we can leverage

**Accumulated Decisions:**
- Dual-mode executor pattern (SDK preferred, httpx fallback) used in all brokers
- Hexagonal architecture with BrokerPort interface

## Tasks

### Task 1: Create connection test endpoint

**What:** Add `POST /accounts/test-connection` endpoint that accepts broker type and credentials, attempts connection, and returns detailed status.

**Files:**
- `app/routers/accounts.py` - Add test-connection endpoint
- `app/application/dto/account_dto.py` - Add TestConnectionRequest/Response DTOs
- `app/application/use_cases/test_connection.py` - New use case

**Acceptance:**
- Endpoint accepts `{ broker: string, credentials: object }`
- Returns `{ success: boolean, status: "connected" | "failed" | "timeout", message: string, details?: object }`
- Works for all 5 broker types: tradelocker, tradovate, projectx, mt4, mt5
- Times out after 10 seconds with clear message
- Returns specific error message for each failure mode

**Verification:**
```bash
# Test with invalid credentials (should return clear error)
curl -X POST http://localhost:8765/accounts/test-connection \
  -H "Content-Type: application/json" \
  -d '{"broker": "tradelocker", "credentials": {"api_key": "invalid", "api_secret": "invalid"}}'
```

### Task 2: Implement broker-specific testers

**What:** Create broker-specific connection test logic in the use case, leveraging existing executor initialization methods.

**Files:**
- `app/application/use_cases/test_connection.py` - Add broker-specific test methods

**Acceptance:**
- TradeLocker: Tests SDK authentication
- Tradovate: Tests API key validation (not OAuth - that's redirect-based)
- ProjectX: Tests API key against ProjectX API
- MT4/MT5: Tests MetaAPI SDK connection or falls back to Manager API ping
- Each test returns broker-specific error messages

**Verification:**
```bash

python -m pytest tests/test_connection_test.py -v
```

  <files>app/domain/exceptions.py</files>
  <action>
    Create domain-specific exception hierarchy. Extract exception patterns from existing codebase but make them framework-independent:

    Base exceptions:
    - `DomainException` - Base for all domain exceptions
    - `ValidationError` - Invalid domain state or input
    - `EntityNotFoundError` - Entity lookup failed
    - `BusinessRuleViolation` - Business rule constraint violated

    Signal exceptions:
    - `SignalValidationError(ValidationError)` - Invalid signal data
    - `SignalProcessingError(DomainException)` - Signal processing failed
    - `DuplicateSignalError(BusinessRuleViolation)` - Signal already processed

    Trading exceptions:
    - `InsufficientBalanceError(BusinessRuleViolation)` - Not enough funds
    - `InvalidOrderError(ValidationError)` - Order validation failed
    - `PositionNotFoundError(EntityNotFoundError)` - Position doesn't exist
    - `OrderNotFoundError(EntityNotFoundError)` - Order doesn't exist

    Account exceptions:
    - `AccountNotFoundError(EntityNotFoundError)` - Account doesn't exist
    - `AccountDisabledError(BusinessRuleViolation)` - Account is inactive
    - `BrokerConnectionError(DomainException)` - Broker communication failed

    Each exception should:
    - Inherit from appropriate base class
    - Accept descriptive message and optional context dict
    - Have __str__ method for clean error messages

    CRITICAL: No imports from FastAPI, SQLAlchemy, or any external framework.
    Only use: dataclasses, typing, enum from standard library.
  </action>

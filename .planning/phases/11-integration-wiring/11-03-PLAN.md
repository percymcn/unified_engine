# Plan 11-03: Wire Accounts Router to Hexagonal Architecture

## Overview

The accounts router currently uses direct SQLAlchemy queries and bypasses the CredentialRepository and EncryptionService. This plan migrates it to use account-related use cases from the DI container, ensuring credentials are properly encrypted.

## Gap Being Closed

From MILESTONE-AUDIT.md:
- "Accounts router uses direct SQL instead of AccountUseCase"
- "Account Management: Breaks at backend → unencrypted credentials"
- "SEC-02: Credentials encryption - Infrastructure exists, but accounts router bypasses it"

## Current State

```python
# app/routers/accounts.py (lines 21-24)
@router.get("/")
async def get_accounts(
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
):
    accounts = db.query(Account).filter(
        Account.user_id == current_user.id
    ).offset(skip).limit(limit).all()
    return accounts
```

**Problems:**
- Direct SQL bypasses repository layer
- No credential encryption
- No domain validation
- No event publishing

## Target State

```python
# app/routers/accounts.py
from app.dependencies import get_container

@router.get("/")
async def get_accounts(
    request: Request,
    current_user: User = Depends(get_current_user),
):
    container = get_container(request)
    use_case = container.list_accounts_use_case()
    accounts = await use_case.execute(user_id=current_user.id)
    return [AccountResponse.from_entity(a) for a in accounts]

@router.post("/")
async def create_account(
    request: Request,
    account_data: AccountCreate,
    current_user: User = Depends(get_current_user),
):
    container = get_container(request)
    use_case = container.create_account_use_case()
    # Credentials encrypted via CredentialRepository
    account = await use_case.execute(
        user_id=current_user.id,
        broker=account_data.broker,
        credentials=account_data.credentials,  # Will be encrypted
    )
    return AccountResponse.from_entity(account)
```

## Tasks

### Task 1: Update Imports
- Remove direct SQLAlchemy Session usage where possible
- Add: `from app.dependencies import get_container`
- Add: `from app.application.use_cases.account import *` (list, create, update, delete use cases)

### Task 2: Migrate GET /accounts Endpoint
- Get container from request
- Use `container.list_accounts_use_case()` or equivalent
- Map domain entities to response DTOs

### Task 3: Migrate POST /accounts Endpoint (Critical)
- This is where credentials must be encrypted
- Use `container.create_account_use_case()`
- Ensure credentials pass through CredentialRepository
- CredentialRepository calls EncryptionService.encrypt_dict()

### Task 4: Migrate PUT /accounts/{id} Endpoint
- Use update use case from container
- Credential updates must re-encrypt

### Task 5: Migrate DELETE /accounts/{id} Endpoint
- Use delete use case from container
- Ensure credentials are properly cleaned up

### Task 6: Migrate GET /accounts/{id}/sync Endpoint
- Use sync use case from container
- Broker adapter from container fetches balance

### Task 7: Add Response Mappers
- Create `AccountResponse.from_entity()` to convert domain entities to API responses
- Ensure credentials never exposed in response (only metadata)

### Task 8: Verify Encryption Flow
- Test account creation
- Check database for encrypted_data column
- Verify decryption works on retrieval

## Security Flow

Account creation now flows through:
1. **Router** → receives credentials in request
2. **CreateAccountUseCase** → orchestrates creation
3. **CredentialRepository.store()** → encrypts and persists
4. **EncryptionService.encrypt_dict()** → Fernet encryption
5. **Database** → stores encrypted_data blob

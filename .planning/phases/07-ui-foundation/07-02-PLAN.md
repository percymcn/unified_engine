Implement self-hosted JWT authentication with login page and route protection.

Purpose: Enable user authentication that works with the existing FastAPI backend. The Next.js app acts as a BFF (Backend For Frontend), proxying auth requests to the Python backend and managing JWT tokens via httpOnly cookies for security.

Output: Working login flow with protected routes and session persistence.
</objective>

       - Server-side functions (for API routes):
         - getTokenFromCookies(cookieStore): Extract token from cookies
         - setTokenCookie(response, token, maxAge): Set httpOnly cookie
         - removeTokenCookie(response): Clear the cookie
       - Client-side helper:
         - isAuthenticated(): Check if auth cookie exists (client-side check)

    IMPORTANT:
    - Use httpOnly cookies for JWT storage (NOT localStorage - security best practice)
    - Cookies should be: httpOnly, secure (in prod), sameSite: 'lax', path: '/'
    - Token verification happens server-side via backend /api/auth/me endpoint

    AVOID: Don't store JWT in localStorage. Don't decode JWT client-side for auth decisions.

       - Extract token from cookie
       - Fetch to `${BACKEND_URL}/api/auth/me` with Authorization header
       - Return user data or 401

    Use NextResponse for responses and cookies() from next/headers for cookie access.

    IMPORTANT: The backend login endpoint expects form data OR query params:

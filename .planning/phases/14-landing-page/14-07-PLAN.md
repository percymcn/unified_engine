# Phase 14 Plan 07: Gap Closure - Middleware & Register Page

## Objective

Close two gaps identified by verification:
1. Middleware redirects "/" away - landing page never displays
2. /register page doesn't exist - CTA buttons are broken

Purpose: Make the landing page actually accessible and fix broken user flows.
Output: Working landing page at root, working /register route.

## Context

### Gap 1: Middleware Blocks Landing Page

From VERIFICATION.md:
```
truth: "Landing page at '/' with modern 2026 design"
status: failed
reason: "Middleware redirects unauthenticated users from '/' to '/login'"
```

Current middleware (lines 73-80):
```typescript
if (pathname === '/') {
  if (isAuthenticated) {
    return NextResponse.redirect(new URL('/dashboard', request.url));
  } else {
    return NextResponse.redirect(new URL('/login', request.url));  // PROBLEM
  }
}
```

Fix: Only redirect authenticated users to dashboard. Let unauthenticated users see the landing page.

### Gap 2: Missing /register Page

From VERIFICATION.md:
```
truth: "CTA buttons link to /register"
status: partial
reason: "/register page does not exist"
```

Hero.tsx and Header.tsx both have CTAs linking to `/register`.

Fix: Create /register page that renders the registration form (or redirects to login with register mode).

## Tasks

### Task 1: Update middleware to allow landing page
**File:** `ui-next/src/middleware.ts`
**Action:** Edit

Change root path handling to only redirect authenticated users:

```typescript
// Root path: Show landing page to visitors, dashboard to authenticated users
if (pathname === '/') {
  if (isAuthenticated) {
    return NextResponse.redirect(new URL('/dashboard', request.url));
  }
  // Unauthenticated users see the landing page
  return NextResponse.next();
}
```

Also update the JSDoc comment at line 53 to reflect the new behavior:
```
* - Root path (/): Show landing page to visitors, redirect to /dashboard if authenticated
```

### Task 2: Create /register page
**File:** `ui-next/src/app/register/page.tsx`
**Action:** Create

Create a register page that either:
- Redirects to /login?mode=register (if login page supports modes)
- Renders the registration form directly

For simplicity, redirect to login since auth forms likely share structure:

```tsx
import { redirect } from 'next/navigation';

export default function RegisterPage() {
  redirect('/login?mode=register');
}
```

Or if login doesn't support modes, create a basic registration page structure that can be enhanced later.

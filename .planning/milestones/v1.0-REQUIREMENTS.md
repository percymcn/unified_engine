## Overview

Requirements for Unified Trading Engine full refactor with hexagonal architecture, new Next.js UI, and comprehensive backend fixes.

**Scope:** v1.0 Refactor Milestone
**Total v1 Requirements:** 33

## Categories

### STAB: Stability Fixes (4 requirements)

Critical fixes to make the existing system run without crashes.

- [x] **STAB-01**: Fix aioredis deprecated import — migrate to redis.asyncio
- [x] **STAB-02**: Fix broker executor initialization crashes — handle missing API keys gracefully
- [x] **STAB-03**: Fix NATS connection timeout issues — proper error handling and fallback
- [x] **STAB-04**: Remove hardcoded API keys from source code — use environment variables

### TEST: Testing Infrastructure (3 requirements)

Get tests passing to have a safety net for refactoring.

- [x] **TEST-01**: Fix test fixtures and setup — 101 tests should run
- [x] **TEST-02**: All 101 existing tests passing
- [x] **TEST-03**: Add test coverage for broker executor error handling

### ARCH: Architecture Refactor (5 requirements)

Hexagonal architecture with clean separation of concerns.

- [x] **ARCH-01**: Domain layer — pure business logic with no framework dependencies
- [x] **ARCH-02**: Application layer — use cases and service orchestration
- [x] **ARCH-03**: Infrastructure layer — concrete implementations (adapters)
- [x] **ARCH-04**: Ports — interfaces defining domain boundaries
- [x] **ARCH-05**: Dependency inversion — domain never imports infrastructure

### BROK: Broker Integration (5 requirements)

All broker executors working with new architecture.

- [x] **BROK-01**: TradeLocker executor — migrated to hexagonal adapter pattern
- [x] **BROK-02**: TopStep/ProjectX executor — migrated to hexagonal adapter pattern
- [x] **BROK-03**: Tradovate executor — migrated to hexagonal adapter pattern
- [x] **BROK-04**: MT4 executor — migrated to hexagonal adapter pattern
- [x] **BROK-05**: MT5 executor — migrated to hexagonal adapter pattern

### SEC: Security Fixes (4 requirements)

Fix security vulnerabilities identified in codebase audit.

- [x] **SEC-01**: Persist encryption key in environment — not generated at runtime
- [x] **SEC-02**: Move credential storage from in-memory to database with encryption
- [x] **SEC-03**: Encrypt OAuth tokens in database
- [x] **SEC-04**: Implement proper API key hashing with salt

### UI: User Interface (9 requirements)

New Next.js 14 dashboard with shadcn/ui.

- [x] **UI-01**: Next.js 14 project setup with shadcn/ui and dark theme
- [x] **UI-02**: Self-hosted JWT authentication flow (login, logout, session)
- [x] **UI-03**: Dashboard layout with navigation
- [x] **UI-04**: Real-time signal status display with WebSocket
- [x] **UI-05**: Broker connection health monitoring
- [x] **UI-06**: Trade execution logs with filtering
- [x] **UI-07**: Account management (CRUD, balances per broker)
- [x] **UI-08**: Signal routing rules configuration
- [x] **UI-09**: API key and webhook endpoint management

### DEPLOY: Deployment (3 requirements)

Production-ready Docker Swarm deployment.

- [x] **DEPLOY-01**: Docker Swarm stack configuration (docker-stack.yml)
- [x] **DEPLOY-02**: Environment-based configuration (dev/staging/prod)
- [x] **DEPLOY-03**: Secret management via Docker secrets

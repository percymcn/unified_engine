## E2E Flow Verification

### Flow 1: Signal Processing ✅ PASSED

**Path:** TradingView webhook → Signal ingestion → Risk checks → Trial checks → Deduplication → Broker execution

**Evidence:**
- `app/routers/webhooks.py` receives webhooks at POST `/api/v1/webhooks/tradingview`
- `ProcessSignalUseCase` called from webhooks.py
- `RiskEnforcementService` evaluates before execution
- `_check_trial_status()` in signal_processor.py auto-starts and validates trial
- `_check_deduplication()` prevents duplicate entries
- `_execute_on_account()` routes to broker adapters

### Flow 2: Billing/Stripe ✅ PASSED

**Path:** Landing page pricing → Stripe checkout → Subscription created → Feature gating

**Evidence:**
- `pricing-section.tsx` renders 4-tier pricing with `getAllTiers()`
- `PricingCard` onClick fetches `/api/billing/checkout`
- BFF route proxies to backend checkout
- `stripe_webhooks.py` handles `checkout.session.completed`
- `update_user_subscription()` applies tier-based gating

### Flow 3: Authentication ✅ PASSED

**Path:** Landing page CTA → Register/Login → Dashboard access

**Evidence:**
- Hero and Header link to `/register` and `/login`
- Register/Login pages submit to BFF `/api/auth/register|login`
- BFF routes proxy to backend with JWT cookie handling
- `middleware.ts` protects `/dashboard/*` routes
- Redirect to `/dashboard` after successful login

### Flow 4: Broker Connection ✅ PASSED

**Path:** Add credentials → OAuth flow → Account fetch → Account selection

**Evidence:**
- TradeLocker dual-mode executor (SDK + Brand API)
- Tradovate OAuth: `/api/v1/auth/tradovate/authorize` and `/callback`
- ProjectX executor integrated in signal_processor.py
- `broker-account-selection.tsx` manages signal routing selection
- `_get_target_accounts()` routes to selected accounts

### Flow 5: Risk Management ✅ PASSED

**Path:** Configure settings → Signal received → Risk checks → Trade blocked/executed

**Evidence:**
- Risk settings UI at `/dashboard/settings/risk`
- `risk.py` provides GET/PUT `/api/v1/risk/settings`
- `RiskEnforcementService` evaluates limits in webhook router
- Blocked signals logged to `RejectedSignal` table
- Trade counters incremented after execution

### Flow 6: Trial System ✅ PASSED

**Path:** First signal → Trial auto-starts → Usage tracked → Upgrade on expiry

**Evidence:**
- `TrialService` with status enum (NOT_STARTED, ACTIVE, EXPIRED)
- `_check_trial_status()` auto-starts on first signal
- `_increment_trial_trade_count()` after execution
- `trial-status-widget.tsx` displays remaining trades/days
- `TrialPromptWrapper` for upgrade prompts

## Minor Observations

### Cookie Name Inconsistency (Low Impact)

- **File:** `ui-next/src/app/api/trial/status/route.ts` line 27
- **Issue:** Checks for `token` cookie, middleware uses `auth-token`
- **Impact:** Graceful degradation returns null, doesn't break flow
- **Recommendation:** Standardize on `auth-token` cookie name

### Risk Settings Direct API Call (Documentation)

- **File:** `ui-next/src/app/dashboard/settings/risk/page.tsx`
- **Issue:** Directly calls `/api/v1/risk/settings` without BFF proxy
- **Impact:** Works with CORS configuration or nginx proxying
- **Recommendation:** Add BFF route for consistency

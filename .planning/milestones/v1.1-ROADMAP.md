# Milestone v1.1: Production Ready with Monetization

**Status:** SHIPPED 2026-01-22
**Phases:** 12-24
**Total Plans:** 47 executed

## Overview

v1.1 transforms Tradeflow from a working signal router into a production-ready SaaS with Stripe monetization, official broker SDKs, comprehensive risk management, and enterprise-grade landing page. Starting from v1.0's hexagonal architecture foundation, we fix critical UI bugs, add billing infrastructure, migrate to official SDKs, implement symbol mapping and multi-account support, and build comprehensive trade controls.

## Milestone Summary

**Key Decisions:**

| Phase | Decision | Rationale |
|-------|----------|-----------|
| 12-01 | Environment variable layering for webhooks | WEBHOOK_BASE_URL > BACKEND_URL > localhost |
| 13-03 | Return 200 on webhook processing errors | Prevent Stripe retries |
| 14-01 | Sticky header with scroll-based transparency | Modern aesthetic |
| 15-01 | Dual-mode TradeLocker (SDK + Brand API) | SDK preferred, API fallback |
| 16-01 | In-memory OAuth state store | Simple for single-instance |
| 17-01 | Dual-mode ProjectX executor | SDK preferred, httpx fallback |
| 18-01 | Use metaapi-cloud-sdk as unified MT4/MT5 API | Official SDK reliability |
| 20-01 | Preserve symbol numbers in normalization | US30, NAS100 are valid |
| 21-02 | Four routing strategies | all_accounts, specific_accounts, rules_based, default_only |
| 22-01 | Close actions bypass all risk checks | Closing should never be blocked |
| 24-01 | Trial auto-starts on first signal | Zero friction UX |
| 24-02 | 4-tier pricing with broker limits | tier_1=1, tier_2=2, tier_3=3, tier_4=4 brokers |

**Issues Resolved:**

- Fixed hardcoded localhost URLs throughout frontend
- Fixed desktop sidebar navigation (z-index, flex-shrink)
- Fixed WebSocket disconnected status
- Fixed dashboard showing placeholder data
- Migrated all 4 broker adapters to official SDKs
- Implemented comprehensive risk management

**Technical Debt Incurred:**

- npm audit: 3 high severity vulnerabilities (dev-only, eslint-related)
- Alembic has multiple heads (001, 002)
- In-memory OAuth state store (needs Redis for multi-instance)

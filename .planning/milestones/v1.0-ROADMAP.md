# Milestone v1.0: Full Refactor

**Status:** ✅ SHIPPED 2026-01-21
**Phases:** 1-11
**Total Plans:** 63

## Overview

Full refactor of the trading signal routing engine from organic growth to clean hexagonal architecture. We start by stabilizing the existing system (critical bug fixes, test infrastructure), then rebuild the backend with proper separation of concerns, build a new Next.js UI, and finish with production deployment configuration. Every phase preserves existing functionality while improving architecture.

## Milestone Summary

**Key Decisions:**

- Full hexagonal architecture chosen over minimal cleanup
- Self-hosted JWT auth (no Supabase)
- Next.js 14 with shadcn/ui for new UI
- All 5 broker integrations must work
- Domain layer strictly isolated from FastAPI, SQLAlchemy
- Fernet symmetric encryption for credential storage
- bcrypt for API key hashing
- httpOnly cookies for JWT storage (XSS protection)
- BFF pattern for UI-to-backend communication

**Issues Resolved:**

- aioredis deprecated import (Phase 1)
- Broker initialization crashes (Phase 1)
- NATS connection timeout handling (Phase 1)
- In-memory credential storage (Phase 6)
- DI Container not initialized (Phase 11)
- Webhook bypassing hexagonal architecture (Phase 11)
- Account credentials unencrypted (Phase 11)

**Issues Deferred:**

- Alembic multiple heads (needs future merge)
- asyncpg not installed (graceful degradation)
- Dashboard stats placeholder data
- WebSocket event bridge incomplete

**Technical Debt Incurred:**

- npm audit shows 3 high severity vulnerabilities (eslint-related, dev-only)
- Old signal processor still exists (deprecated but functional)
